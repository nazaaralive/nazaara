# Nazaara Website — Handoff for the next Cowork session

Written 2026-06-07 as a working reference for whoever picks up this repo next. Companion doc to `nazaara-sms/docs/CLAUDE_HANDOFF.md`, which covers the separate SMS platform this site posts opt-ins to.

## What this app is

`nazaara` is the public marketing website for **Nazaara Live**, a Bollywood/desi events promoter. Live at **https://nazaara.live**. It shows upcoming events (city-targeted via edge geo), lets people book private events, hosts artist/DJ rosters and galleries, and is the CMS for all of the above. Praj Chadha (`contact@nazaara.live`) is the sole operator and admin user.

The site is the source of truth for event/artist/venue data. The SMS opt-in component embedded on the site pushes new subscribers to the separate `nazaara-sms` app.

- **uploadthing** for image uploads (venue images, artist images, gallery images, event hero images).

- **Vercel** hosts everything. Project `prj_t9N8agK6J1h7j107pG19iFbk4Jqn` in team `nazaara` / `team_PH3L0j9zhc2xEVIft1i0xt9y`. Auto-deploy from `main` on GitHub.

## Data model (Drizzle)

Main tables in `src/db/schema.ts`:

- **venues** — `id, slug (UNIQUE), name, description, address, addressUrl, city, country, images[], imageKeys[], createdAt, updatedAt`. Indexed on slug/name/city.
- **artists** — `id, slug (UNIQUE), name (UNIQUE), instagram, soundcloud, image, imageKey, createdAt`. Roster entities.
- **events** — main entity, joined to venue + artists via junction. Has `slug, title, tagline, description, date, image, imageKey, status (draft/published), isFeatured, isTour, ticketUrl, startTime, endTime, cityOverride, countryOverride, venueId`.
- **events_artists** — junction (`eventId, artistId, order`), primary key on the pair.
- **event_stops** — for tour events: `eventId, city, country, venue, startTime, endTime, ticketUrl, order`.
- **galleries** — `id, slug, title, description, date, coverImage, coverImageKey, createdAt`.
- **gallery_images** — `id, galleryId, url, key, order, caption, createdAt`. Composite index on `(galleryId, order)`.
- **djs** — DJ roster for the bookings page: `id, slug, name, bio, image, imageKey, instagram, soundcloud, mixcloud, priceRange, createdAt`.
- **site_settings** — key-value store for site-wide toggles/copy (single row).

Auth tables in `src/db/auth-schema.ts` (managed by better-auth):

- **user** — `id, name, email (UNIQUE), emailVerified, image, role, banned, banReason, banExpires, createdAt, updatedAt`.
- **session** — active sessions with expiresAt/ipAddress/userAgent/token/impersonatedBy.
- **account** — provider link records (for OAuth if added later; password login uses email/password on user).
- **verification** — email verification tokens.

## Route map

Public:

- `GET /` — home. Server component. Fetches upcoming events via `getPublicUpcomingEvents()`. Middleware adds `nza_city` / `nza_country` cookies used by the Hero to show a city-targeted CTA.
- `GET /event/[event-slug]` — individual event page.
- `GET /galleries` and `/galleries/[slug]` — photo galleries.
- `GET /about`, `/bookings`, `/dj-roster`, `/privacy`, `/terms`.
- `GET /sms` — dedicated SMS opt-in page. **This URL is registered as the Twilio A2P 10DLC campaign's End User Consent CTA — do not rename or delete without updating the TCR submission (see nazaara-sms docs/a2p-* files).**
- `GET /r/:token` — rewrites (via `next.config.ts`) to `https://nazaara-sms.vercel.app/r/:token` so branded SMS click links resolve on `nazaara.live` but are actually handled by the SMS app's redirect endpoint.

Admin (all auth-gated, `middleware.ts` checks for `better-auth.session_token`):

- `/admin` — dashboard with tabs for events, artists, DJs, venues, galleries, users, settings.
- `/admin/auth` — sign-in page.
- `/admin/setup` and `/admin/setup/complete` — first-run admin creation flow.
- `/admin/{venues,djs,artists,events,galleries}/new` — creation forms.
- `/admin/{venues,djs,artists,events,galleries}/[slug]` — edit pages.

API:

- `POST /api/auth/[...all]` — better-auth handler (sign-in, sign-out, session, admin).
- `POST /api/uploadthing` — uploadthing file router.

## Middleware (`middleware.ts`, edge runtime)

Two jobs:

1. **Admin gate** — any `/admin/*` path other than `/admin/auth` redirects to `/admin/auth` if there's no `better-auth.session_token` (or `__Secure-…` variant). Role check is done server-side inside the pages themselves.
2. **Geo cookies** — reads `req.geo?.city/country`, or `x-vercel-ip-city/country`, or `cf-ipcity/ipcountry`. Sets `nza_city` and `nza_country` cookies (httpOnly, sameSite=lax, 3-day maxAge). **Cookie value is URL-encoded** because raw multi-word city names (`Los Angeles`) contain spaces that make browsers silently drop the Set-Cookie — the comment in the file explains the bug that this defense fixes. `decodeCityName()` in `src/lib/event-time.ts` reverses it on read.

Matcher: `["/", "/events", "/about", "/bookings", "/admin/:path*"]`. **Note: `/events` is in the matcher but there's no `/events` route — it's a dead entry, harmless.**

## SMS opt-in integration

- Component: `src/components/home/sms-optin.tsx` (client component, 323 lines).
- Rendered inline in the site footer and as the whole content of `/sms`.
- Posts to `https://nazaara-sms.vercel.app/api/optin-public` with `{phone, name, city, source, marketingOptIn, transactionalOptIn, acceptedTerms}`.
- `source` prop lets you tag opt-in origin (footer vs `/sms` page vs future landing pages). Currently: `"website_footer"` default, `"sms_page"` on the dedicated page.
- **Compliance rules baked into the form**: phone is optional; name/city/city are optional; every checkbox is optional and unchecked by default. Nothing gates submission (TCPA forced-consent). The backend decides what to do based on which boxes were ticked.
- Client-side `normalizePhone` accepts 10-digit US/CA, 11-digit starting with 1, or `+…` E.164. Sends normalized to the backend.
- Success states: `success` (subscribed), `already` (already subscribed), `saved` (form accepted but nothing subscribed because required boxes weren't ticked), `error`.

**⚠️ Discrepancy to verify**: the file currently contains three checkboxes — `transactionalOptIn`, `marketingOptIn`, `acceptedTerms`. An earlier commit (`f5dbc0a`, "Remove transactional SMS checkbox from opt-in form") purportedly removed the transactional one, but the current on-disk version still shows it (lines 34, 66, 91, 106, 114, 251–262). Either the removal was reverted after that commit, or the earlier session's summary was wrong. Before touching this file, run `git log -- src/components/home/sms-optin.tsx` and compare against production to know which state is actually live. The TCR submission for the new campaign (`CMd3d29672822bac62cc316c7ed96551a0`) is written for a **marketing-only** flow — so if transactional is live on the form, the description and form are out of sync and TCR will reject.

## Auth (`src/lib/auth.ts`)

- `betterAuth()` with Drizzle adapter, Postgres provider, email + password enabled.
- `plugins: [nextCookies(), admin({...})]` — admin plugin reads `process.env.ADMIN_USER_IDS` (comma-separated user IDs) to grant admin role.
- **Security issue**: `trustedOrigins` array contains the string `"*"` with a comment "Trust all domains (for debugging - not recommended for production)" — this defeats the entire origin check. **Fix before shipping any more:** remove the wildcard and the placeholder `your-domain.com` entries, list only real Nazaara origins.
- **Boilerplate leftover**: multiple entries reference `your-domain.com`. Clean up.
- **Console logs**: the file logs the entire config bootstrap to stdout at every cold start. Fine for debugging, noisy in production — consider gating behind `NODE_ENV !== "production"`.

## Data-fetching pattern

Server actions everywhere. Two files:

- `src/lib/public-actions.ts` (~600 lines): `getPublicEvents`, `getPublicUpcomingEvents`, `getPublicFeaturedEvent`, `getPublicEventStops`, `getPublicEventForCity` (uses the geo cookie), `getPublicEventBySlug`, `getPublicGalleries`, `getPublicGalleryBySlug`. Called from server components with `revalidate = 0` for fresh data on every request.
- `src/lib/admin-actions.ts` (~1300 lines): CRUD for events / artists / venues / galleries / DJs, plus stats, slug availability check, autosave, and file deletion. All wrapped in `"use server"` — called directly from admin forms.

Public list pages use `export const revalidate = 0` so cache doesn't stale after admin edits. If you need caching, revisit.

## Known bugs / cleanup items

### 1. `trustedOrigins: ["*"]` in `src/lib/auth.ts`
Wildcard-trust of all origins defeats better-auth's CSRF/origin protection. Real security issue. **Fix**: replace with the actual production/preview/localhost origins and remove the `your-domain.com` placeholders.

### 2. `sms-optin.tsx` may be out of sync with TCR campaign description
See "Discrepancy to verify" above. If transactional checkbox is still live on the form but the TCR submission describes marketing-only, TCR will reject. Reconcile.

### 3. Middleware matcher includes `/events` but no such route exists
`middleware.ts` matcher: `["/", "/events", "/about", "/bookings", "/admin/:path*"]`. `/events` is dead — real event pages are at `/event/[event-slug]`. Harmless, but confusing. **Fix**: drop `/events` from the matcher (or add a `/events` index route if intended).

### 4. `src/scripts/fix-db.ts` — one-shot repair script
Presence in the repo suggests it was a specific migration/repair. Check whether it's still relevant; if not, delete. Same review for `src/scripts/check-venue.ts`.

### 5. Client-side and server-side phone normalization drift
`sms-optin.tsx` `normalizePhone()` (lines 40-46) uses a slightly different regex than `nazaara-sms/api/optin-public.js`. The client accepts anything starting with `+` and 11+ digits, but strips non-digit-plus chars. Server does its own normalization. If they drift further, users could see mismatched validation. **Fix**: extract to a shared source, or make both maximally permissive with server-side truth.

### 6. `revalidate = 0` on every public page
Fresh-data-per-request is right today but eats Vercel function invocations. Once event data cadence is understood, consider ISR (`revalidate = 60`) or on-demand revalidation from `admin-actions.ts` after writes. Would meaningfully reduce serverless usage.

### 7. Turbopack for build (`next build --turbopack`)
Turbopack build is still relatively new. Watch for edge-case build failures; the escape hatch is `next build` (webpack). Not urgent — flag only.

### 8. `/r/:token` rewrite depends on nazaara-sms
The click-tracking rewrite in `next.config.ts` sends `/r/:token` on `nazaara.live` to `nazaara-sms.vercel.app/r/:token`. If the SMS app is down, every SMS link on nazaara.live 502s. **Fix**: consider a graceful fallback (redirect to `/` on error) or accept the coupling — it's inherent to the branded-link approach.

### 9. `console.log` in `src/lib/auth.ts`
Fires on every cold start in production. Noisy. Gate behind `NODE_ENV !== "production"` or delete.

### 10. Migrations directory has 18 files
Not a bug — just a heads-up. Any schema changes need `drizzle-kit generate` to create the next-numbered migration. Don't hand-edit past migrations.

## Rules of engagement for the next session

- **The site is production and public.** Every deploy is user-visible immediately. Test admin changes on preview branches if there's any doubt.
- **TCR compliance is fragile.** The `/sms` page URL, the opt-in form field structure, and the welcome SMS text on the backend are all baked into the Twilio A2P 10DLC campaign registration. Changing any of them may require re-submitting to TCR (which has already gone through 4 rounds — read the SMS repo's `docs/a2p-*` files before making changes).
- **Admin auth is real.** Don't disable middleware auth checks even for "quick testing" — leave short-lived signed-in sessions or use `impersonateUser` if debugging on prod.
- **Event data is authoritative.** The nazaara Postgres is the source of truth for events, venues, artists, DJs. Don't script writes that skip the admin forms — the forms enforce slug uniqueness, image key tracking, and other invariants.
